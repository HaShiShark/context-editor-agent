# Long Context 15-Task Benchmark Tasks

这个任务清单用于连续投喂 Codex。执行规则：15 个任务按顺序发送，中途不逐个验收，不把失败结果反馈给 Codex；最后统一检查完成数和总成本。

Hash Context 组压缩节点：

- T05 完成后压缩一次。
- T10 完成后压缩一次。

## T01 顶部菜单从假按钮变成真实下拉菜单

位置：主窗口左上角顶部栏，“文件 / 编辑 / 查看 / 窗口 / 帮助”。

任务要求：

- 点击每个菜单名都能打开一个下拉菜单。
- 点击其他菜单时，当前菜单关闭并打开新菜单。
- 点击页面空白处或按 `Esc` 时关闭菜单。
- 菜单不需要实现所有复杂功能，但不能再只是 hover 变色的假按钮。
- 菜单样式要和当前暗色 UI 一致，不要做系统默认白底菜单。

菜单内容最低要求：

- 文件：新建对话、新建项目。
- 编辑：复制、清空当前输入区。
- 查看：放大、缩小、重置缩放。
- 窗口：最小化、最大化、关闭。
- 帮助：关于 hashcode。

验收：

- 顶部菜单项是可点击交互控件。
- 每个菜单至少有 1 个可见下拉项。
- `Esc` 和点击外部能关闭菜单。

## T02 帮助菜单增加真实的“关于 hashcode”弹窗

位置：顶部栏 `帮助` 菜单。

任务要求：

- 点击 `帮助 -> 关于 hashcode` 后，在应用内打开一个小弹窗。
- 弹窗展示：产品名、当前版本、项目简介、GitHub 链接、README 链接。
- 版本号必须读取项目里的 `package.json` 版本，不允许写死。
- 弹窗可以关闭。
- GitHub / README 点击后用系统默认浏览器打开外部链接，不要在 Electron 页面内跳转。

验收：

- “关于 hashcode”不是 toast，而是可关闭弹窗。
- 版本号和 `package.json` 一致。
- 外部链接点击不会导致 Electron 页面内跳转空白页。

## T03 顶部“查看”菜单接入窗口缩放

位置：顶部栏 `查看` 菜单。

任务要求：

- `查看` 菜单里提供：放大、缩小、重置缩放。
- 复用当前 Electron 已有的缩放能力，和 `Ctrl + +`、`Ctrl + -`、`Ctrl + 0` 行为一致。
- 菜单项点击后菜单关闭。
- 缩放范围仍遵守当前最小/最大限制。

验收：

- 点击放大后 UI 明显变大。
- 点击缩小后 UI 明显变小。
- 点击重置缩放后恢复 100%。

## T04 主设置页工具列表增加搜索

位置：主设置页，不是上下文工作台设置页。路径是左侧导航进入 `设置 -> 工具`。

任务要求：

- 在工具列表顶部增加搜索框。
- 搜索范围包括工具名、工具 label、工具描述。
- 输入关键词后只显示匹配工具。
- 没有匹配时显示空状态文案。
- 清空搜索后恢复全部工具。
- 不影响工具开关的保存逻辑。

验收：

- 搜索 `read` 能筛出读文件相关工具。
- 搜索不存在的词时出现“没有匹配工具”类空状态。
- 搜索后切换工具开关仍然能保存。

## T05 主设置页工具列表增加“一键启用 / 一键禁用”

位置：主设置页 `设置 -> 工具`。

任务要求：

- 在工具列表顶部增加两个按钮：全部启用、全部禁用。
- 点击后只修改当前工具设置，不影响模型、provider、外观等其他设置。
- 点击后仍需要走现有保存逻辑，不能只改 UI 临时状态。
- 如果所有工具已启用，“全部启用”按钮可以 disabled。
- 如果所有工具已禁用，“全部禁用”按钮可以 disabled。

验收：

- 全部禁用后，所有工具开关都关闭。
- 保存刷新后状态还在。
- 全部启用后，所有工具开关都开启。

压缩检查点：Hash Context 组在 T05 后进行第一次手动压缩。

## T06 主聊天多工具调用合并成一个折叠组

位置：主聊天区 assistant 消息里的工具调用展示。

任务要求：

- 当一个 assistant 回复里连续出现多个工具调用块时，UI 顶层只显示一个工具组。
- 组标题显示真实数量，例如 `调用了 3 个工具`。
- 不允许每个工具都单独显示 `调用了 1 个工具`。
- 单工具场景仍然能正常展示。
- 工具组默认折叠还是展开，可以沿用当前风格，但行为要稳定。

验收：

- 构造含 3 个 tool block 的 assistant 消息时，只出现一个组标题。
- 组标题数量为 3。
- 展开后能看到 3 个工具项。

## T07 多工具组内显示每个工具的名称和状态

位置：主聊天区 assistant 工具折叠组内部。

任务要求：

- 展开工具组后，每个工具作为一行展示。
- 每行至少展示：工具名称、成功/失败状态。
- shell 类工具额外展示命令预览。
- 单个工具详情仍可继续展开查看完整输出。

验收：

- 成功工具和失败工具视觉上能区分。
- shell 工具能看到命令预览。
- 多工具组里每个工具都能单独展开详情。

## T08 上下文工作台新增真实 Usage 页

位置：右侧上下文工作台，不是主设置页，也不是建议页里的 token 估算区域。

任务要求：

- 在右侧上下文工作台 tabs 中新增 `Usage / 用量` 页。
- Usage 页展示真实模型调用返回的 usage 累计值，不使用前端上下文估算 token 代替。
- Usage 按当前 session 统计，至少分为三块：会话总用量、主聊天用量、上下文工作台用量。
- 每块至少展示：输入 token、缓存输入 token、非缓存输入 token、输出 token、reasoning token、cache 命中率。
- 非缓存输入 token 由 `输入 token - 缓存输入 token` 计算。
- 不同 provider 返回的 usage 字段可能不同：能识别就归一化，缺失的字段显示 `0`，页面不能报错。
- 不做成本估算，不展示美元价格。
- 提供 `重新计数` 按钮，只清空当前 session 的 usage，不清空聊天记录、上下文和 revision。

验收：

- 工作台能看到 `Usage / 用量` tab。
- 主聊天完成一次模型调用后，主聊天用量增加。
- 手动页完成一次上下文模型调用后，上下文工作台用量增加。
- 非缓存输入 token 等于输入 token 减缓存输入 token。
- 点击重新计数后，当前 session 的 Usage 归零，但聊天记录和上下文版本不变。

## T09 建议页增加“压缩优先级”区域

位置：右侧上下文工作台 `建议` 页。

任务要求：

- 在建议页新增一个区域，名字可以叫“压缩优先级”。
- 这个区域提示先处理哪些节点。
- 至少给出 3 类判断：token 最大的节点、工具输出占比最高的节点、已经超过红色阈值的节点。
- 每条建议必须包含原因，比如“节点 #7 工具输出占比最高，适合先压缩工具结果”。
- 没有红色节点时，也要给出“当前没有高占用节点”的正常状态。

验收：

- 有上下文时，不只是列 token 数，而是出现可读建议。
- 建议里包含节点编号和原因。
- 没有红色节点时页面不空。

## T10 建议页节点点击后定位到上下文地图

位置：右侧上下文工作台 `建议` 页 + 左侧上下文地图。

任务要求：

- 建议页里的节点项可以点击。
- 点击后，上下文地图滚动到对应节点。
- 对应节点出现短暂高亮。
- 这个行为不能改变节点选中状态，除非用户明确点击 gutter 选中。
- 如果右侧面板当前没有完全展开，需要尽量保持现有布局，不要强行改 stage 行为。

验收：

- 点击建议里的节点 #N 后，地图滚动到 #N。
- #N 有明显高亮。
- 原本选中的节点集合不被误改。

压缩检查点：Hash Context 组在 T10 后进行第二次手动压缩。

## T11 恢复页增加“对比当前版本”

位置：右侧上下文工作台 `恢复` 页。

任务要求：

- 每个非当前版本的 revision 卡片上增加“对比当前版本”按钮。
- 点击后展示一个对比摘要。
- 对比摘要至少包含：当前版本节点数、目标版本节点数、节点数差异、当前版本估算 token、目标版本估算 token、token 差异、发生变化的节点编号列表。
- 这里只做查看，不执行恢复。

验收：

- 点击对比不会改变当前上下文。
- 能看到节点数和 token 差异。
- 能看到变化节点列表。

## T12 恢复页对比结果支持“只看变化节点”

位置：右侧上下文工作台 `恢复` 页的对比结果。

任务要求：

- 在 T11 的对比结果里增加一个切换项：全部节点 / 只看变化节点。
- “只看变化节点”模式下，只展示有差异的节点摘要。
- 每个变化节点至少展示：节点编号、角色、当前版本摘要、目标版本摘要。
- 如果没有变化，显示“两个版本没有可见节点差异”。

验收：

- 切换后列表数量会变化。
- 只看变化节点时，不显示完全相同的节点。
- 不影响恢复功能。

## T13 手动页新增 AB 压缩模式

位置：右侧上下文工作台 `手动` 页。

任务要求：

- 在手动页输入区附近增加一个开关：`AB 压缩模式`。
- 开启后，这一轮只服务“压缩上下文”场景。
- 用户可以输入类似：“压缩节点 #4-7”。
- 模型第一步只能读取节点信息、分析上下文，不能改上下文。
- 模型需要先给出两个候选压缩摘要：A 版本更保守，尽量保留细节；B 版本更激进，尽量节省 token。
- 用户输入 `A` 或 `B` 后，才允许真正执行压缩并生成 revision。
- 用户输入其他内容时，继续解释让用户选择 A 或 B。
- 这个功能只对压缩生效，不支持删除、替换、恢复。

验收：

- 开启 AB 压缩模式后，第一轮生成 A/B 候选不会产生 revision。
- 用户选择 A 或 B 后才产生 revision。
- revision 摘要能看出选择的是 A 还是 B。
- 模式开启时，删除/替换类操作被拒绝或不会执行。

## T14 AB 压缩模式增加清晰的状态提示

位置：右侧上下文工作台 `手动` 页。

任务要求：

- 当 AB 压缩模式开启时，输入框上方显示当前模式状态。
- 至少有 3 个状态：未开始、待选择、已应用。
- 状态提示要告诉用户当前能做什么，不能做什么。
- 关闭 AB 压缩模式时，清空未完成的 A/B 待选择状态。
- 切换会话时，也要清空未完成状态。

验收：

- 开关打开后能看到 AB 模式提示。
- 生成候选后提示变成等待 A/B。
- 选择后提示变成已应用。
- 关闭开关后待选择状态消失。

## T15 工作台设置增加默认打开页

位置：右侧上下文工作台 `设置` 页，不是主设置页。

任务要求：

- 在工作台设置页增加“默认打开页”配置。
- 可选项：建议、手动、恢复、Usage、设置。
- 保存后持久化。
- 重新打开应用或切换会话后，工作台默认进入用户选择的页。
- 如果用户选择了 Usage，但 Usage tab 不存在或加载异常，要 fallback 到建议页。

验收：

- 设置默认打开页为 Usage 后，刷新应用仍然生效。
- 设置为手动后，重新进入工作台默认是手动页。
- 不影响主设置页。
